# Contributing

Thank you for helping improve Project Status or RunGlance.

## Before opening a change

1. Open or reference an issue for material behavior changes.
2. Keep readiness, live activity, evidence validity, and service health as
   separate concepts.
3. Preserve the local-first privacy boundary and the read-only MCP boundary.
4. Edit canonical skill sources under `skill/`; do not hand-edit generated
   plugin wrappers.
5. Add focused tests and update documentation for changed contracts.

Run the repository checks documented in [README.md](./README.md). Generated
wrappers must be synchronized only after canonical skill and MCP source changes
are complete.

## Conduct and security

Be respectful, specific, and evidence-oriented. Do not post credentials,
private paths, prompts, transcripts, customer data, or vulnerability details
in public issues. Report suspected security problems through
[SECURITY.md](./SECURITY.md).
